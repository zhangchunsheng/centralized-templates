## Project Overview

A local clone of the [DataEase Template Market](https://templates.dataease.cn/) built with Vue 3 + Vite 3. It fetches all free templates (metadata, screenshots, and template files) from the upstream Halo app-store API and builds a static, searchable, filterable site where users can download templates locally.

## Common Commands

```bash
# Install dependencies
npm install

# Fetch / refresh template data (downloads screenshots to public/uploads/
# and template files to public/templates/, then writes src/data/templates.json)
npm run fetch:data

# Start the Vite dev server
npm run dev

# Production build (outputs to dist/)
npm run build

# Preview the production build locally
npm run preview
```

## Architecture

### Data Flow

1. `scripts/fetch-templates.mjs` calls `https://templates.dataease.cn/apis/api.store.halo.run/v1alpha1/applications?page=0&size=500`.
2. It downloads each screenshot and template file, normalizing filenames and deduplicating assets.
3. It writes `src/data/templates.json`, which contains the localized list of templates with local paths like `/uploads/...` and `/templates/...`.
4. The Vue app imports that JSON directly via the Pinia store (`src/stores/templates.js`) and renders it with no runtime API dependency.

### Frontend

- **Entry**: `src/main.js` mounts the app with Pinia and Vue Router.
- **Routing**: `src/router/index.js` defines `/`, `/template/:id`, and a catch-all 404.
- **State**: `src/stores/templates.js` holds the template list and all filter/search state. Filtering is pure frontend.
- **Labels**: `src/constants/labels.js` maps upstream enums (`templateType`, `templateClassification`, `label`) to Chinese display names.
- **Styling**: Tailwind CSS; primary color is `blue-600` mapped through `primary-*`. Global styles are in `src/assets/styles/main.css`.
- **Static assets**: `public/uploads/` (images) and `public/templates/` (`.DET`, `.DET2`, `.DET2APP` files) are generated by the fetch script and are gitignored.

### Build & Deployment

- Vite is configured with `base: './'` so the built SPA can be served from a subdirectory.
- `dist/` includes the bundled app plus the contents of `public/`.
- Because it is a SPA, the hosting server must fallback unknown paths to `index.html` (see README.md Nginx example).

## Important Notes

- Do not commit `public/uploads/` or `public/templates/`; they are ignored. A fresh clone must run `npm run fetch:data` before the site has usable assets.
- `src/data/templates.json` is generated but should remain in Git so the app can build without re-fetching.
- `scripts/failed.log` records any upstream assets that 404 or are unreachable (e.g., internal IP links); this is expected and can usually be ignored.
- The upstream template files use mixed extensions (`.DET`, `.DET2`, `.DET2APP`, etc.). The fetch script preserves them.
